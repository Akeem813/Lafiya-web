# Error Budget Policy

**Owner:** On-call platform team lead  
**Status:** Active  
**Related:** `docs/operations/mainnet-assurance.md`, `scripts/compute-error-budget.mjs`

---

## Purpose

This document defines who owns the decision to release when the error budget is
exhausted, what process must be followed for an override, and how the budget is
computed and surfaced in the release workflow.

---

## SLO and budget

The error budget is derived from the **public-card availability SLO**:

| Property | Value |
|---|---|
| SLO target | 99.9% successful live card resolutions |
| Measurement window | 30-day rolling (720 hours) |
| Allowed error rate | 0.1% (1 failure per 1,000 probes) |
| Source | Synthetic probes + route-class request counters |

An error budget of 100% means no budget has been consumed in the current
window. An error budget of 0% means the full allowed error rate has been used.

---

## Multi-window burn-rate thresholds

Burn rate is defined as: `actual error rate / allowed error rate`.  
A burn rate of 1.0 means budget is being spent at exactly the SLO rate.

| Severity | Window | Burn-rate threshold | Meaning |
|---|---|---|---|
| **page** | 1h | ≥ 14.4 | ~1% budget consumed in 1 hour |
| **page** | 6h | ≥ 6.0 | ~5% budget consumed in 5 hours |
| **warn** | 24h | ≥ 3.0 | ~10% budget consumed in 1 day |
| **warn** | 72h | ≥ 1.0 | Budget on pace to exhaust by end of window |

These thresholds follow the Google SRE multi-window burn-rate model
(SRE Workbook, Chapter 5). They are implemented in
`scripts/compute-error-budget.mjs`.

---

## Release gate behaviour

The `mainnet-release.yml` workflow runs `compute-error-budget.mjs` when a
`probes_path` input is provided. The gate behaviour is:

| Budget state | Alert severity | Gate outcome |
|---|---|---|
| Healthy (consumed < 100%) | none | ✅ PASS |
| Elevated consumption | warn | ✅ PASS (warning surfaced) |
| High burn rate | page | 🚫 BLOCKED |
| Exhausted (consumed ≥ 100%) | any | 🚫 BLOCKED |

The remaining budget percentage is surfaced in the GitHub Actions step summary
on every release run, regardless of gate outcome.

---

## Override process

When the gate blocks a release, a deployer may supply an `override_reason` in
the workflow dispatch inputs. The following conditions apply:

1. **The reason must be non-empty.** Blank overrides are rejected.
2. **The reason must describe why the deployment is safe**, e.g.:
   - "Critical auth regression fix — only affects sign-in route, not card availability"
   - "Rollback to last known-good revision — reduces error rate"
3. **The override is automatically recorded** by `scripts/record-budget-override.mjs`
   to `release-evidence/budget-overrides.jsonl` with the actor, timestamp,
   build revision, run ID, and workflow name.
4. **Only fix, urgent, or rollback deployments** are accepted (`--type` values).

### Who owns the override decision

The **on-call platform team lead** owns the decision to deploy during budget
exhaustion. A second reviewer (independent of the deployer) must have approved
the release in the GitHub mainnet environment (via the `environment: mainnet`
required-reviewer control) before the workflow can proceed at all — this is the
separation-of-duties gate that the override reason supplements.

The override record is auditable: anyone with read access to the repository
can inspect `release-evidence/budget-overrides.jsonl`.

## Probe data format

The gate accepts a JSON array of probe results at `probes_path`:

```json
[
  {
    "timestamp": "2026-10-22T12:00:00Z",
    "success": true,
    "latencyMs": 320
  }
]
```

- `timestamp`: ISO-8601 datetime of the probe.
- `success`: `true` if the card resolved correctly; `false` otherwise.
- `latencyMs`: Optional. Not used by the budget gate but available for p95 analysis.

Probes are generated by the synthetic monitoring infrastructure and should be
exported to a file before the release workflow runs.

## Maintenance

- Review thresholds every quarter in the on-call review meeting.
- If the SLO target changes, update `SLO_TARGET` in `compute-error-budget.mjs`
  and regenerate the fixture commitment values.
- Archive `budget-overrides.jsonl` entries older than 1 year to cold storage.
